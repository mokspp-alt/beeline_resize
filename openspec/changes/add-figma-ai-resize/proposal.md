# Proposal

## Why

Дизайнеры вручную адаптируют каждый макет под десятки размеров: брейкпоинты сайта, экраны iOS/Android-приложения, рекламные и социальные форматы баннеров. Это часы рутинной работы на каждый макет, ошибки при соблюдении дизайн-системы и расхождения между платформами. Нужен AI-инструмент внутри Figma, который из одного исходного макета собирает все нужные размеры, опираясь на дизайн-систему, а не на «тупое» масштабирование.

## What Changes

- Новый **Figma-плагин** `beeline_resize`: дизайнер выбирает один исходный фрейм, выбирает целевую платформу (Web / App / Баннеры) и набор размеров, нажимает «Адаптировать» — на странице появляются новые фреймы для каждого размера.
- Новый **AI-бэкенд**: принимает описание исходного макета, определяет смысловые роли элементов (заголовок, CTA, логотип, герой-изображение, навигация, юридический текст и т.д.) и строит план раскладки для каждого целевого размера.
- **Каталог размеров по умолчанию** (определён в спеке `size-presets`): Web-брейкпоинты, экраны App (iOS и Android, телефоны и планшеты), дисплейные баннеры (IAB/РСЯ) и социальные форматы; плюс пользовательские размеры.
- **Подключение дизайн-системы Carnica**: плагин использует шесть библиотек Figma — `01_Carnica-colors-2.0`, `02_Carnica-typography`, `03_Carnica-sizes` (токены), `04_Carnica-icons` (иконки), `05_Carnica-UI-kit-APP` и `06_Carnica-UI-kit-WEB` (компоненты). Web-размеры собираются из UI-kit WEB, App-размеры — из UI-kit APP. Сгенерированные фреймы переключают моды переменных (брейкпоинт, платформа) и варианты компонентов под целевой размер вместо ручного изменения значений.
- **Два режима адаптации**: UI-режим (Web и App — перестройка сетки и колонок, платформенные элементы: safe area, статус-бар, таб-бар, адаптивные хедер/футер) и баннерный режим (иерархия элементов, безопасные зоны, кадрирование изображений по фокусной точке, минимальные размеры текста).
- **Подключаемый LLM-провайдер**: выбор модели в конфигурации бэкенда (Anthropic, OpenAI-совместимый API, GigaChat, YandexGPT), детерминированный фолбэк без LLM.

## Capabilities

### New Capabilities

- `figma-source-capture`: чтение выбранного исходного фрейма в плагине, валидация и сериализация в промежуточное описание макета.
- `size-presets`: каталог целевых размеров по платформам (Web, App iOS/Android, баннеры, соцсети), пользовательские размеры и наборы.
- `design-system-integration`: подключение дизайн-системы Carnica (библиотеки токенов, иконок, UI-kit WEB и APP) — компоненты и варианты, переменные и моды, стили, сетки; выбор UI-kit по платформе; правила соответствия «размер → мод/вариант/компонент».
- `layout-adaptation`: построение плана раскладки исходного макета под целевой размер в UI-режиме (Web/App) и баннерном режиме, с LLM и детерминированным фолбэком.
- `figma-output-generation`: создание результирующих фреймов в Figma по плану, именование и размещение, отчёт о проблемах.
- `llm-provider`: подключаемый LLM-провайдер на бэкенде — конфигурация, структурированный ответ, таймауты, политика данных.

## Impact

- Репозиторий `beeline_resize` (сейчас пустой): появляются пакеты `plugin` (Figma-плагин), `backend` (AI-сервис), `shared` (схемы описания макета и плана раскладки, каталог размеров).
- Внешние зависимости: Figma Plugin API, API выбранного LLM-провайдера.
- Доступ к сети из плагина ограничен доменом бэкенда (manifest `networkAccess`).
- Данные макетов (структура, тексты, по желанию — превью) уходят на бэкенд и в LLM-провайдера: требуется согласование политики данных; для чувствительных макетов — провайдер в контуре РФ / on-prem.
- Все шесть библиотек Carnica должны быть опубликованы и включены (Assets → Libraries) в файле, в котором работает плагин.
- Для сканирования библиотек через REST API бэкенду нужен Figma-токен с доступом на чтение к файлам Carnica; чтение переменных через REST доступно только на тарифе Enterprise, поэтому переменные сканируются из плагина.
