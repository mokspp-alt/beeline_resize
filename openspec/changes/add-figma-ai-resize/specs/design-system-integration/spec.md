## Purpose

Подключает дизайн-систему Carnica к адаптации, чтобы результаты для Web, App и баннеров собирались из компонентов, токенов и стилей Carnica, а не из произвольных значений.

## ADDED Requirements

### Requirement: Carnica library set
Плагин SHALL работать с набором библиотек Carnica из конфигурации: colors, typography, sizes, icons, UI-kit APP, UI-kit WEB. Плагин MUST показывать статус каждой библиотеки (включена в файле / не включена).

#### Scenario: Все библиотеки включены
- **WHEN** все шесть библиотек Carnica включены в текущем файле
- **THEN** плагин показывает «Carnica подключена» и шесть библиотек со статусом «включена»

#### Scenario: Не включён UI-kit
- **WHEN** в файле не включена библиотека `06_Carnica-UI-kit-WEB`
- **THEN** плагин показывает её со статусом «не включена» с подсказкой «Assets → Libraries», а адаптация под Web выполняется без переключения вариантов и замен компонентов, что отражается в отчёте

#### Scenario: Не включены токены
- **WHEN** в файле не включена ни одна из библиотек colors, typography, sizes
- **THEN** плагин предупреждает, что результаты не будут привязаны к токенам Carnica, и продолжает только после подтверждения пользователя

### Requirement: Platform UI kit selection
Система SHALL брать компоненты для режима `web` из UI-kit WEB, а для режима `app` — из UI-kit APP. Если исходник собран на компонентах одного UI-kit, а целевой размер относится к другой платформе, компоненты MUST заменяться на соответствующие компоненты другого UI-kit по конфигурации соответствия.

#### Scenario: Web-исходник в App-размер
- **WHEN** исходник 1440 собран на кнопке `Button` из UI-kit WEB, целевой размер 393×852, а в конфигурации задано соответствие с `Button` из UI-kit APP
- **THEN** в результате используется кнопка из UI-kit APP с тем же текстом

#### Scenario: Нет соответствия между китами
- **WHEN** для компонента UI-kit WEB нет соответствия в UI-kit APP
- **THEN** компонент остаётся из UI-kit WEB, а в отчёте указано «нет App-аналога для <имя компонента>»

### Requirement: Icons from the icon library
При замене или изменении размера иконок система SHALL использовать компоненты библиотеки `04_Carnica-icons` и размеры иконок из токенов `03_Carnica-sizes`; иконки MUST NOT масштабироваться в размеры, отсутствующие в дизайн-системе.

#### Scenario: Иконка в мобильном размере
- **WHEN** иконка 32 в исходнике 1440 должна уменьшиться для 360×auto, а в токенах есть размеры иконок 16, 24, 32
- **THEN** иконка в результате имеет размер 24 или 16 из токенов, а не промежуточное значение

### Requirement: Design system mapping config
Система SHALL хранить конфигурацию соответствия дизайн-системы: какие коллекции переменных отвечают за брейкпоинт, платформу и тему; какие моды соответствуют каким классам размеров; какие компоненты имеют платформенные или размерные варианты. Конфигурация MUST загружаться с бэкенда.

#### Scenario: Конфигурация загружена
- **WHEN** плагин запускается и бэкенд отдаёт конфигурацию соответствия
- **THEN** плагин использует её для всех адаптаций в этой сессии

#### Scenario: Автообнаружение для черновой конфигурации
- **WHEN** администратор запускает в плагине «Сканировать дизайн-систему»
- **THEN** плагин выводит найденные коллекции переменных с модами и компоненты с вариантами в виде черновой конфигурации для проверки и сохранения

### Requirement: Variable mode switching
Для каждого результирующего фрейма система SHALL устанавливать явный мод коллекций переменных, соответствующий целевому размеру (например, мод брейкпоинта и мод платформы), чтобы отступы, типографика и радиусы брали значения токенов этого мода.

#### Scenario: Web-брейкпоинт
- **WHEN** исходник сделан для 1440, а целевой размер 360×auto, и в конфигурации класс `mobile` соответствует моду `Mobile` коллекции `Breakpoints`
- **THEN** у результирующего фрейма установлен мод `Mobile` коллекции `Breakpoints`

#### Scenario: Платформа App
- **WHEN** целевой размер из группы `app-android`, а в конфигурации коллекция `Platform` имеет моды `iOS` и `Android`
- **THEN** у результирующего фрейма установлен мод `Android` коллекции `Platform`

### Requirement: Component variant switching
Для инстансов компонентов дизайн-системы система SHALL переключать вариант на соответствующий целевому размеру и платформе по конфигурации соответствия, сохраняя overrides текста и контента.

#### Scenario: Размер кнопки
- **WHEN** в исходнике 1440 кнопка `Button` с вариантом `Size=L`, а конфигурация задаёт `Size=M` для класса `mobile`
- **THEN** в результате 360×auto кнопка имеет вариант `Size=M` и тот же текст

#### Scenario: Платформенный компонент
- **WHEN** в исходнике iOS-экрана используется `NavigationBar` с вариантом `Platform=iOS`, а целевой размер Android
- **THEN** в результате используется вариант `Platform=Android` того же компонента

### Requirement: Component substitution
Конфигурация SHALL позволять задать замену компонента целиком для класса размеров (например, `Header/Desktop` → `Header/Mobile`); система MUST выполнять замену, перенося совпадающие по имени текстовые свойства.

#### Scenario: Хедер сайта
- **WHEN** в исходнике 1440 используется `Header/Desktop`, а для класса `mobile` задана замена на `Header/Mobile`
- **THEN** в результате 360×auto используется `Header/Mobile`, текстовые свойства с совпадающими именами перенесены

### Requirement: Design system compliance
Новые значения, которые система задаёт в результатах (отступы, размеры шрифта, радиусы, цвета), SHALL браться из переменных и стилей дизайн-системы, если подходящий токен существует. Значения без токена MUST попадать в отчёт как отклонения.

#### Scenario: Отступ из токена
- **WHEN** план требует уменьшить gap с 32 до 16, и в дизайн-системе есть переменная `spacing/16`
- **THEN** gap результата привязан к переменной `spacing/16`, а не задан числом

#### Scenario: Отсутствующий токен
- **WHEN** план требует размер шрифта 13, а такого стиля или переменной нет
- **THEN** значение применяется числом и фрейм помечается в отчёте отклонением «нет токена для font-size 13»
