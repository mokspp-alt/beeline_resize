# Spec Delta

## Purpose

Даёт бэкенду единый способ обращаться к языковой модели для решений по раскладке, с выбором провайдера в конфигурации и контролем данных, ключей, времени ответа и стоимости.

## ADDED Requirements

### Requirement: Configurable provider
Бэкенд SHALL поддерживать провайдеров `anthropic`, `openai-compatible` (включая локальные/on-prem модели с OpenAI-совместимым API), `gigachat` и `yandexgpt`; активный провайдер и модель MUST выбираться конфигурацией без изменения кода.

#### Scenario: Смена провайдера
- **WHEN** администратор меняет в конфигурации провайдера с `anthropic` на `gigachat` и перезапускает бэкенд
- **THEN** последующие адаптации используют GigaChat, а плагин работает без изменений

### Requirement: Credentials stay on backend
Ключи доступа к провайдерам SHALL храниться только на бэкенде (переменные окружения или хранилище секретов) и MUST NOT передаваться в плагин или попадать в логи.

#### Scenario: Ответ плагину
- **WHEN** плагин запрашивает конфигурацию с бэкенда
- **THEN** ответ содержит имя провайдера и модели, но не содержит ключей

### Requirement: Structured output
Каждый ответ модели SHALL проверяться по схеме ожидаемого результата (роли элементов, план раскладки). При несоответствии бэкенд MUST сделать одну повторную попытку с описанием ошибки и затем перейти к детерминированному фолбэку.

#### Scenario: Невалидный JSON
- **WHEN** модель вернула ответ, не проходящий схему, и повторная попытка тоже невалидна
- **THEN** для этого размера используется детерминированный фолбэк, а в отчёте указано «без AI: невалидный ответ модели»

### Requirement: Timeouts and limits
Бэкенд SHALL ограничивать время ответа модели (по умолчанию 30 с на запрос) и число параллельных запросов на пользователя, а также вести учёт токенов на запуск.

#### Scenario: Превышение таймаута
- **WHEN** модель не ответила за 30 с
- **THEN** запрос прерван и используется детерминированный фолбэк

### Requirement: Data policy
Бэкенд SHALL поддерживать настройку политики данных: разрешена ли отправка растровых превью, разрешена ли отправка текстов макета как есть или с маскированием, список провайдеров, допустимых для конфиденциальных файлов. Запросы, нарушающие политику, MUST NOT отправляться провайдеру.

#### Scenario: Превью запрещено политикой
- **WHEN** политика запрещает растровые превью, а плагин прислал превью
- **THEN** бэкенд не передаёт превью провайдеру и работает только по структурному описанию

#### Scenario: Маскирование текстов
- **WHEN** включено маскирование текстов
- **THEN** провайдеру передаются длины и роли текстов, а сами тексты заменены плейсхолдерами

### Requirement: Plugin authentication
Бэкенд SHALL принимать запросы только от авторизованных пользователей плагина (командный токен или вход через корпоративный SSO) и MUST отклонять запросы без валидной авторизации кодом 401.

#### Scenario: Запрос без токена
- **WHEN** на API адаптации приходит запрос без авторизации
- **THEN** бэкенд отвечает 401 и не обращается к LLM-провайдеру
