# Spec Delta

## Purpose

Определяет, под какие размеры адаптируется макет: каталог целевых разрешений для Web, App (iOS/Android) и баннеров по умолчанию, а также пользовательские размеры и наборы.

Все размеры указаны в единицах Figma (1x: px для Web, pt для iOS, dp для Android). Размер записывается как «ширина×высота»; `auto` по высоте означает, что высота определяется содержимым.

## ADDED Requirements

### Requirement: Preset catalog structure
Система SHALL предоставлять каталог размеров, сгруппированный по платформам: `web`, `app-ios`, `app-android`, `banner-display`, `banner-social`. Каждый размер MUST иметь id, имя, группу, ширину, высоту (число или `auto`), ориентацию и класс (`mobile`, `tablet`, `desktop`, `banner`).

#### Scenario: Пользователь видит группы
- **WHEN** пользователь открывает выбор размеров в плагине
- **THEN** размеры показаны по группам Web, App iOS, App Android, Баннеры, Соцсети, с указанием ширины и высоты каждого

### Requirement: Web breakpoint presets
Группа `web` SHALL по умолчанию содержать брейкпоинты шириной 360, 390, 768, 1024, 1280, 1440 и 1920 с высотой `auto`. Если подключённая дизайн-система задаёт свои брейкпоинты, группа `web` MUST использовать брейкпоинты дизайн-системы вместо значений по умолчанию.

#### Scenario: Брейкпоинты по умолчанию
- **WHEN** дизайн-система не задаёт брейкпоинты и пользователь выбирает группу Web целиком
- **THEN** целевые размеры: 360×auto, 390×auto, 768×auto, 1024×auto, 1280×auto, 1440×auto, 1920×auto

#### Scenario: Брейкпоинты из дизайн-системы
- **WHEN** в дизайн-системе есть коллекция переменных брейкпоинтов с модами Mobile=360, Tablet=768, Desktop=1440
- **THEN** группа Web содержит 360×auto, 768×auto и 1440×auto

### Requirement: iOS app presets
Группа `app-ios` SHALL по умолчанию содержать экраны: iPhone SE 375×667, iPhone 13 mini 375×812, iPhone 16e 390×844, iPhone 16 393×852, iPhone 17 / 17 Pro 402×874, iPhone Air 420×912, iPhone 17 Pro Max 440×956, iPad mini 744×1133, iPad Air 11" 820×1180, iPad Pro 13" 1032×1376.

#### Scenario: Выбор iPhone-набора
- **WHEN** пользователь выбирает набор «iOS — телефоны»
- **THEN** целевые размеры: 375×667, 375×812, 390×844, 393×852, 402×874, 420×912, 440×956

#### Scenario: Выбор iPad-набора
- **WHEN** пользователь выбирает набор «iOS — планшеты»
- **THEN** целевые размеры: 744×1133, 820×1180, 1032×1376

### Requirement: Android app presets
Группа `app-android` SHALL по умолчанию содержать экраны по классам окон Material: Compact 360×800, Compact 412×917, Medium (складной / малый планшет) 700×840, Expanded (планшет, портрет) 800×1280, Expanded (планшет, ландшафт) 1280×800.

#### Scenario: Выбор Android-телефонов
- **WHEN** пользователь выбирает набор «Android — телефоны»
- **THEN** целевые размеры: 360×800 и 412×917

### Requirement: Display banner presets
Группа `banner-display` SHALL по умолчанию содержать форматы IAB и РСЯ: 300×250, 336×280, 300×300, 300×600, 240×400, 160×600, 728×90, 970×250, 320×50, 320×100.

#### Scenario: Все дисплейные форматы
- **WHEN** пользователь выбирает группу Баннеры целиком
- **THEN** создаются 10 целевых размеров из списка группы `banner-display`

### Requirement: Social banner presets
Группа `banner-social` SHALL по умолчанию содержать форматы: квадрат 1080×1080, пост 4:5 1080×1350, сторис/клипы 1080×1920, превью ссылки 1200×630, обложка 16:9 1920×1080.

#### Scenario: Вертикальный формат
- **WHEN** пользователь выбирает «Сторис/клипы»
- **THEN** целевой размер 1080×1920 с ориентацией portrait и классом banner

### Requirement: Custom sizes and saved sets
Пользователь SHALL иметь возможность добавить произвольный размер (ширина и высота от 16 до 8192) и сохранить набор выбранных размеров под именем. Наборы MUST сохраняться между сессиями для этого пользователя.

#### Scenario: Пользовательский размер
- **WHEN** пользователь вводит 1000×120 и нажимает «Добавить»
- **THEN** размер появляется в группе «Пользовательские» и доступен для выбора

#### Scenario: Недопустимый размер
- **WHEN** пользователь вводит 0×120 или 10000×120
- **THEN** размер не добавляется и показано сообщение о допустимом диапазоне

#### Scenario: Сохранённый набор
- **WHEN** пользователь сохранил набор «Промо-лендинг» и перезапустил плагин
- **THEN** набор «Промо-лендинг» доступен с теми же размерами

### Requirement: Team catalog override
Администратор SHALL иметь возможность заменить каталог по умолчанию командным каталогом в конфигурации бэкенда; плагин MUST получать актуальный каталог с бэкенда при запуске.

#### Scenario: Обновление каталога без релиза плагина
- **WHEN** администратор добавил в командный каталог формат 1000×120 в группу `banner-display`
- **THEN** при следующем запуске плагина формат доступен всем пользователям без обновления плагина
